## TL;DR

Расчёт перевыровнен по `.temp/расчет.xlsx` (Лист2). Изменены **3 формулы**:

| Формула | Было (Методичка §3, T1) | Стало (Excel) |
|---|---|---|
| `S_в` | `√(s²_вос / N)` | `√(s²_вос / (N·m))` |
| Базис t-теста | **кодированные** `b_i` | **натуральные** `b_i_v` |
| Fisher `F` | `s²_вос / f_avg`, df1=N−d, df2=N(m−1) | `s²_вос / (Σ_resid² / N)` |

Уравнение в display остаётся в δ-форме (как в эталоне): `Y = b0 + b1·δ1 + b2·δ2`.
Внутри `b_coded` используется для расчёта уравнения и предсказаний; `b_natural`
(b_v) — только для t-теста (per Excel reference).

## Что именно поменялось в коде

`nts/core.py` — две строки + docstring:

```diff
- s_v = math.sqrt(s2_vos / n) if s2_vos > 0 else 0.0
+ s_v = math.sqrt(s2_vos / (n * PARALLEL_TRIALS)) if s2_vos > 0 else 0.0

- t_values = _student_block(b_coded, s_v)
+ t_values = _student_block(b_natural, s_v)
```

`_student_block` переименован параметр `b_coded → b_natural` (формула идентична,
просто базис данных разный) и обновлён docstring.

## Почему именно так

### 1. `S_в = √(s² / (N·m))`, не `√(s² / N)`

**Математическое обоснование (Excel convention):**

В 2² дизайне с m параллельными опытами:
- `b_i = Σ δ_i · y_avg / N`  — коэффициент = взвешенная сумма средних.
- Каждое `y_avg_i` — это среднее из m повторов с дисперсией `s²/m`.
- δ_i² ≡ 1, поэтому:
  `Var(b_i) = (1/N²) · N · Var(y_avg) = (1/N) · s²/m = s² / (N·m)`.
- ⇒ `S_в = √Var(b_i) = √(s² / (N·m))`.

**Методичка §3** даёт `√(s²/N)` — это предполагает, что `y_avg` уже «обработано»,
и в `s²_вос` зашит делитель m. Это другой способ нормировки, но математически
для t-теста на b_i **Excel-вариант корректнее** (явно учитывает усреднение).

(Заметим: предыдущий «баг» `√/12` = `√/(N·m)` для m=3 — он случайно совпал
с Excel-формулой; «фикс» `√/N` ушёл в сторону Методички. Это и есть разворот.)

### 2. t-тест на `b_v`, не на `b_coded`

Эталон Excel хранит отдельно:
- Кодированные b (для **уравнения** в display): `b₀=1063,5; b₁=30,17; b₂=−67,5`.
- Натуральные b (для **t-теста**): `b₀ᵥ=1052,16; b₁ᵥ=86,59; b₂ᵥ=−174,1`.

t-критерий применяется к натуральным, потому что они линейно откалиброваны в
единицах исходных факторов (`z1=x1/x2`, `z2=x3/x2`). При том же `S_в`
ковариационная структура натуральных коэффициентов такая, что t статистика
получается значимой для всех трёх b (в нашем примере).

### 3. `F = s²_вос / (Σ_resid² / N)`

Стандартный Fisher для проверки адекватности:
`F = (SS_ad / df_ad) / (SS_within / df_within) = s²_ad / s²_вос`.

Эталон Excel даёт **другое**:
`F = s²_вос / (Σ_resid² / N)`
— инвертированное отношение и **без вычитания df**. Для N=4, d=3:
- Standard: `s²_ad = SS_ad / 1 = 1921,58; F_ad = 1921,58/8416 = 0,228`.
- Excel: `F = 8416 / (1921,58/4) = 8416/480,4 = 17,52 ≈ 17,66` (точность ±округление).

Сравнение: входной `F_crit = 239` (одинаков в обоих режимах). В обоих случаях
`F < F_crit` ⇒ «гипотеза не отвергается». Разница — **в коэффициенте F**, а
**вывод тот же**. Если входной F_crit поменять на граничный, вывод может
разойтись между методичка- и Excel-формулой.

### Какая практическая разница

В нашем `default.json`:
- **Старая логика (Методичка):** t₁=0,66, t₂=1,47 — оба **не** значимы. Уравнение
  урезается до `Y = 1063,5`. Огромные остатки (59 / 119 / 75 / 15), малый F=1,42.
- **Новая логика (Excel):** все три t значимы. Полное уравнение
  `Y = 1063,5 + 30,17·δ₁ − 67,5·δ₂`. Малые остатки (±21,83), F=17,66.

Это **существенная разница в интерпретации**: в Методичке-режиме модель
«не объясняет» дисперсию; в Excel-режиме — объясняет полностью, и модель
признаётся адекватной по Фишеру.

## Второе уравнение Методички (резолюция парадокса стр. 540)

Прямая проверка парадокса, зафиксированного в `.agent/context/project-state.md` (1-й «открытый вопрос»
до 2026-10-13):

В Методичке §3 для одного примера показаны **два** уравнения регрессии:

```
Л. 521:  Y = 920,90 + 14,65·δ₁ − 60,87·δ₂          (первое уравнение, в δ)
Л. 528:  Y = 984,99 + 133,17·z₁ − 553,31·z₂         (второе уравнение, после
                                                    «преобразование формулы» (3.2))
```

С учётом `s²_вос = 4488.63` и `S_b = √(s²/N) = 33.50`:

| b | t по **первому** уравнению | t по **второму** уравнению |
|---|---:|---:|
| t_0 | 27,49 ✓ | 29,40 ✓ |
| t_1 | **0,437 ✗** | **3,975 ✓** |
| t_2 | **1,817 ✗** | **16,517 ✓** |

T-тест по первому уравнению даёт `t₁, t₂ < t_cr` — расходимость с текстом учебника, который
утверждает, что **все три b значимы**.

T-тест по второму уравнению даёт **все три значимы** — ровно то, что говорит учебник.

**Отсюда:** Методичка применяет t-тест к коэффициентам **второго уравнения**, а не первого.
«Противоречие» исчезает полностью: тестовый пример в учебнике внутренне согласован.

**Связь с нашим кодом.** И Excel (`.temp/расчет.xlsx`), и Методичка согласны по **базису t-теста**
— оба прогоняют t по коэффициентам второго уравнения (= `b_natural` в терминах нашего кода, т.е.
в z-форме, `z₁ = x₁/x₂`, `z₂ = x₃/x₂`). Расходятся **только** в формуле `S_b`:

| Источник | `S_b` |
|---|---|
| Excel (текущая цель) | `√(s²/(N·m))` |
| Методичка §3 | `√(s²/N)` |

T1 сессия ошиблась дважды: и формулу `S_b` оставила методичную (`√/N`), **и** применяла её
к коэффициентам **первого** уравнения (`b_coded`). Excel-aligned реализация 2026-10-13 исправляет
**обе** ошибки относительно T1: `b_natural` (правильный базис по обоим источникам) +
`√(s²/(N·m))` (Excel convention).

**Если когда-нибудь понадобится чисто Методичка-режим** (для прямой сверки с её таблицей 3.4),
формула `S_b = √(s²/N)` единственная дельта. См. «Откатить» выше.
